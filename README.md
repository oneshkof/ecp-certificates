# Учёт электронных цифровых подписей (ЭЦП)

Десктопное приложение на C# (Windows Forms, .NET 8) для автоматизации учёта
электронных цифровых подписей сотрудников, отслеживания сроков их действия
и координации заявок на получение новых сертификатов.

## Возможности

- **Реестр выданных ЭЦП** — ведение записей о выданных и архивных сертификатах.
- **Заявки на получение ЭЦП** — отслеживание процесса оформления и обновления подписей.
- **CRUD** — добавление, просмотр, редактирование и удаление записей.
- **Автоматическое поле «Осталось дней»** — вычисляется как *Дата окончания − Текущая дата*.
  Записи с истёкшим сроком подсвечиваются красным, с истекающим (≤ 30 дней) — жёлтым.
- **Кнопка «Проверить сейчас»** — показывает список сертификатов, истекающих в течение 30 дней.
- **Строка состояния** — внизу окна выводится статистика: всего сотрудников, просрочено,
  истекает в течение 30 дней.
- **Сортировка** — клик по заголовку любого столбца сортирует данные по возрастанию/убыванию.
- **Экспорт в Excel (.xlsx)** — кнопка вызывает системный диалог сохранения файла.
- **Локальная БД SQLite** — файл `ecp.db` создаётся в папке проекта.

### Модуль уведомлений (Email / Telegram)

Программа автоматически проверяет срок действия сертификатов и отправляет
уведомления в **Telegram** при приближении критической даты.

- **Канал:** Telegram-бот (через Bot API по HTTPS, без сторонних библиотек).
- **Пороги:** по умолчанию за **30, 14 и 7** дней до окончания (настраивается).
- **Когда проверяется:** при запуске программы и далее по таймеру
  (по умолчанию раз в сутки).
- **Адресат:** уведомление уходит **лично сотруднику, привязанному к записи ЭЦП**
  (поле «Telegram сотрудника» / «Telegram Chat ID»). Если Telegram не указан —
  запись пропускается.
- **Текст уведомления:** ФИО сотрудника, подразделение, номер сертификата,
  дата окончания и точное количество оставшихся дней.
- **Защита от повторов:** отправленные пороги сохраняются в поле
  `NotifiedThresholds`, повторно по одному порогу сообщение не уходит.

**Как привязать сотрудника к сертификату:**
1. Сотрудник должен один раз написать боту `/start` в Telegram.
2. В записи ЭЦП укажите его **Telegram** — `@username` (без @) или числовой Chat ID.
3. При наступлении порога уведомление придёт **именно ему**.

**Настройка бота (в приложении):**
1. Создайте бота у [@BotFather](https://t.me/BotFather) → получите токен.
2. Откройте кнопку **«Настройки уведомлений»** и вставьте токен бота.
3. Кнопкой **«Обновить подписчиков»** можно синхронизировать список тех,
   кто написал боту `/start` (используется для сопоставления @username → Chat ID).

Настройки хранятся в файле `notification-settings.json` рядом с базой данных.
Этот файл и токен бота исключены из Git (см. `.gitignore`).

## Структура данных

База данных содержит **8 связанных таблиц**:

| # | Таблица | Назначение |
|---|---|---|
| 1 | `Departments` | Справочник подразделений |
| 2 | `Employees` | Сотрудники |
| 3 | `CertificateAuthorities` | Удостоверяющие центры (УЦ) |
| 4 | `CertificateTypes` | Справочник типов сертификатов |
| 5 | `Certificates` | Реестр выданных ЭЦП |
| 6 | `RequestTypes` | Справочник типов получения заявок |
| 7 | `RequestStatuses` | Справочник статусов заявок |
| 8 | `Requests` | Заявки на получение ЭЦП |

### Таблица «Certificates» (Реестр выданных ЭЦП)
| Поле | Тип | Описание |
|---|---|---|
| Id | INTEGER PK | Идентификатор |
| FullName | TEXT | ФИО сотрудника |
| EmployeeId | INTEGER FK → Employees | Связь с сотрудником |
| DepartmentId | INTEGER FK → Departments | Подразделение |
| AuthorityId | INTEGER FK → CertificateAuthorities | Удостоверяющий центр |
| CertificateTypeId | INTEGER FK → CertificateTypes | Тип сертификата |
| SerialNumber | TEXT | Серийный номер сертификата |
| StoreLogin | TEXT | Логин к хранилищу сертификатов |
| StorePassword | TEXT | Пароль к хранилищу сертификатов |
| CertPassword | TEXT | Пароль от самой ЭЦП |
| IssueDate | TEXT | Дата выдачи |
| ExpiryDate | TEXT | Дата окончания действия |
| Comment | TEXT | Комментарий |
| NotifiedThresholds | TEXT | Пороги, по которым уже отправлены уведомления |
| TelegramUsername | TEXT | Telegram сотрудника (@username) |
| TelegramChatId | TEXT | Telegram Chat ID сотрудника |

Поле «Осталось дней» не хранится, а вычисляется в приложении.

### Таблица «Requests» (Заявки на получение ЭЦП)
| Поле | Тип | Описание |
|---|---|---|
| Id | INTEGER PK | Идентификатор |
| FullName | TEXT | ФИО сотрудника |
| EmployeeId | INTEGER FK → Employees | Связь с сотрудником |
| RequestNumber | TEXT UNIQUE | Номер заявки |
| RequestType | TEXT | Тип: Новый / Замена / Обновление данных |
| RequestTypeId | INTEGER FK → RequestTypes | Тип получения |
| RequestStatusId | INTEGER FK → RequestStatuses | Статус заявки |
| CreatedDate | TEXT | Дата создания |
| CertificateId | INTEGER FK → Certificates | Связь с сертификатом |

### Справочные таблицы
- **Departments** — подразделения для выпадающего списка.
- **Employees** — сотрудники (ФИО, подразделение, должность, e-mail).
- **CertificateAuthorities** — удостоверяющие центры (название, ИНН).
- **CertificateTypes** — типы сертификатов.
- **RequestTypes** — типы получения заявок.
- **RequestStatuses** — статусы заявок.

Связи между таблицами реализованы через внешние ключи (`FOREIGN KEY`) с
включённым `PRAGMA foreign_keys = ON`. По внешним ключам созданы индексы.

## Требования для запуска

- **ОС:** Windows 10/11 (Windows Forms — платформа Windows).
- **.NET SDK 8.0** или новее — [скачать](https://dotnet.microsoft.com/download).
  Проверить: `dotnet --version`.
- **IDE (по желанию):** Visual Studio 2022 (с workload «.NET desktop development»)
  или Visual Studio Code с расширением C# Dev Kit.

## Установка зависимостей

Зависимости (NuGet-пакеты) восстанавливаются автоматически при сборке:

| Пакет | Назначение |
|---|---|
| `Microsoft.Data.Sqlite` | Встроенная реляционная БД SQLite |
| `ClosedXML` | Формирование файлов Excel `.xlsx` |

Ручное восстановление при необходимости:

```powershell
dotnet restore
```

## Сборка и запуск

Из папки с решением `WindowsFormsApp1`:

```powershell
# Сборка
dotnet build

# Запуск
dotnet run --project WindowsFormsApp1

# Публикация готового приложения (self-contained, без установки .NET)
dotnet publish WindowsFormsApp1 -c Release -r win-x64 --self-contained
```

Либо просто откройте `WindowsFormsApp1.slnx` в Visual Studio и нажмите **F5**.

## База данных

Файл `ecp.db` создаётся **в папке проекта** (`WindowsFormsApp1\WindowsFormsApp1\ecp.db`) —
это делает путь к БД стабильным и удобным для редактирования во время разработки.
В готовой (опубликованной) сборке, где файла проекта нет, база кладётся рядом
с исполняемым файлом.

Схема создаётся автоматически при первом запуске. Для сброса данных достаточно
удалить `ecp.db` (при следующем запуске он создастся заново).

Файл базы данных исключён из Git (см. `.gitignore`), чтобы не коммитить
локальные данные.
